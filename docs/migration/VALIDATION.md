# 验证范围

本轮只执行 Java 迁移需要的有限验证，未恢复 Go 测试或压力测试，未启动 Redis、Kafka、Docker 或额外 MySQL，也未连接、修改用户现有数据库。

## 已执行

完整串行构建通过：协议 75 项、网关 56 项、持久化 26 项、客户端 18 项，共 175 项测试，失败/错误/跳过均为 0。网关、持久化和客户端均已打包为可执行 JAR，帮助入口不会创建服务连接。

- 协议测试：无符号 64 位用户 ID、101/102/103 字段、可信连接身份、Unicode 长度、帧大小、点赞范围和严格时间解析。
- 网关核心测试：房间隔离、订阅代际与退订竞争、Kafka 确认后广播、有界工作队列、慢连接和退出路径。
- Netty 测试：EmbeddedChannel 与短时本机回环连接；完整握手、编码路径、提前发送、分片/二进制/超限处理、连接限额和绑定失败清理。另通过完整管线暂缓写完成、输入 Ping，验证自动 Pong 的帧数/字节上限、超限关闭和缓冲释放。
- Kafka producer 测试：MockProducer 手动确认、失败回调、发送队列和在途限额、取消与关闭。
- Redis 适配测试：受控异步命令响应、订阅确认与清理、键和 TTL、超过 2^53 的精确整数、溢出和命令失败。
- 网关启动测试：配置解析、无效 Redis 数据库提前拒绝、敏感配置脱敏、部分启动失败回收、关闭顺序和有限等待；使用受控资源工厂，不创建真实数据客户端。
- 持久化测试：H2 中的整批事务、UUID 去重、历史查询边界；MockConsumer 中的先写后确认、失败重放、有限重试、退出与部分启动失败清理。
- 客户端测试：命令解析、接收分片、错误退出；另用实际 Java 客户端连接临时 Netty 网关，验证弹幕回显、uint64 身份、点赞统计和 `/quit`。该冒烟检查只有一个客户端，数据服务使用替身。

各阶段先验证失败场景，再实现或修复，通过独立代码审查后分别提交。最终构建命令为 `mvn -o -B -T1 package`；离线模式要求依赖已缓存，普通首次构建使用 `mvn -B -T1 package`。构建资源限制见 [构建说明](BUILD.md)，各模块结果与提交记录见 [进展](PROGRESS.md)。

最后的构建过程中，房间统计测试曾出现一次等待超时。受控诊断确认：刷新失败已可观察时，前一轮调度仍可能尚未结束，下一次手动触发会被正常合并。该测试现已停用自身的周期定时器，并逐次等待手动调度结束后再释放受控结果；原有不重叠、人数、帧数和 TTL 断言均保留，未修改生产核心。最终 12 个正式测试类全部通过，临时诊断类已移出构建。

整体代码审查和修复复查已通过：自动 Pong 绕过发送限额、CLI 异常关闭被当作成功这两个问题均已关闭。没有遗留或搁置的代码审查问题；以下真实环境验证事项仍保留。

## 尚未验证

- 真实 MySQL 8.4 上的 Flyway 迁移、排序规则、Connector/J 批量重写及故障行为。H2 不能证明这些 MySQL 特有行为。
- Kafka broker 的副本确认、消费组重平衡、位点协调和网络中断。MockProducer/MockConsumer 不能代替 broker 集成。
- Redis Lua 的实际执行、连接重建、网络超时和跨网关传播。当前脚本面向 standalone Redis，不支持 Redis Cluster。
- 完整基础设施链路、真实操作系统信号下的进程退出，以及长时间运行的资源稳定性。
- Java 吞吐、延迟分位数、GC 和内存容量，以及相同可靠性语义下的 Java/Go 性能对比。

以上保留为后续验证事项，不将单元测试结果表述为真实全链路或性能保证。

## 执行选择与取舍

- 固定上游代码快照，而不合并无关 Git 历史，以保留目标仓库的初始提交和小步迁移记录；原项目的历史需通过上游仓库或本地参考分支查阅。
- Kafka broker 确认后才广播，避免明确被 Kafka 拒收的消息先广播；代价是与原 Go 不同的延迟语义，后续性能对比需对齐。
- 本机没有 Git Bash，使用 PowerShell 完成辅助操作；这些操作未作为可移植脚本发布，正式构建入口仍为 Maven。
- Maven 骨架下载依赖时允许独立编写协议测试，实际测试和生产实现仍按依赖顺序推进；整体验证负责发现可能的接口错位。
- 房间核心与持久化的独立文件可并行编写，JVM 构建和测试始终串行；通过最终完整构建检查跨模块组合，避免并发测试增加主机负担。
